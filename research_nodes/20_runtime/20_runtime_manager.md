# Runtime Manager

## Статус

**Research task prepared.** Этот файл предназначен для отдельной самостоятельной проработки компонента.

## Вводная

Host-side управляющий слой, отвечающий за жизненный цикл Android Runtime.

## Что требуется проработать

- Mount preparation.
- Binder allocation.
- LXC lifecycle.
- Network namespace.
- Logging, health state, restart policy.
- D-Bus/CLI/API управления.

## Задание на исследование

Проанализировать lifecycle-менеджеры Waydroid, LXC/systemd и аналогичных проектов. Спроектировать runtime-manager как distro-neutral system service для Debian.

При проработке необходимо:

1. Найти существующие проекты, реализации, библиотеки, патчи и design documents, решающие аналогичную или близкую задачу.
2. Для каждого релевантного решения определить:
   - что именно оно решает;
   - насколько оно активно и актуально;
   - какие assumptions делает;
   - какие части можно переиспользовать;
   - какие части несовместимы с нашей архитектурой.
3. Сформировать не менее двух реалистичных вариантов реализации, если задача допускает альтернативы.
4. Выбрать рекомендуемый вариант и аргументировать выбор.
5. Определить необходимые изменения/адаптацию существующего кода.
6. Сформировать PoC, который проверяет главный технический риск компонента.
7. Составить поэтапный план реализации.
8. Указать зависимости от других узлов проекта и интерфейсы между ними.
9. Зафиксировать неизвестные, риски и вопросы, требующие эксперимента.
10. Привести ссылки на первичные источники и исходный код.

## Что должно появиться в этом файле после проработки

- Архитектура daemon/service.
- State machine запуска и остановки.
- CLI/D-Bus API.
- Failure/recovery model.
- Интеграция с systemd и logging.

## Связь с общей архитектурой

Основная host-база проекта — Debian. Android Runtime не должен зависеть от Droidian, Ubuntu Touch, Sailfish OS или конкретной mobile shell. Эти проекты используются как reference implementations. Для устройств с хорошей mainline-поддержкой следует учитывать Mobian/postmarketOS и native Linux backend.
